  126: =head1 DESCRIPTION
  127: 
  128: Lingua::Text is a simple container that stores the same piece of text in
  129: multiple languages inside a single Perl object.  When you ask the object to
  130: print itself (or convert to a string), it automatically reads the user's
  131: operating-system language setting and returns the correct translation.
  132: 
  133: =head2 How language detection works
  134: 
  135: The module reads the following environment variables, in this order, and uses
  136: the first one it finds that contains a two-letter language code:
  137: 
  138: =over 4
  139: 
  140: =item 1. C<LANGUAGE> (space- or colon-separated preference list, e.g. C<fr:en>)
  141: 
  142: =item 2. C<LC_ALL>
  143: 
  144: =item 3. C<LC_MESSAGES>
  145: 
  146: =item 4. C<LANG> (e.g. C<en_US.UTF-8> or C<de_DE>)
  147: 
  148: =back
  149: 
  150: Only the first two letters are used (e.g. C<en_GB.UTF-8> becomes C<en>), so
  151: you only need to store one translation per language, not per locale variant.
  152: 
  153: If none of these variables is set, or if C<LANG> is set to the POSIX C<C>
  154: or C<C.UTF-8> locale, the module returns C<undef> (or C<'en'> for the C
  155: locale).
  156: 
  157: =head2 How string interpolation works
  158: 
  159: The object overloads Perl's C<""> (stringify) operator.  This means you can
  160: use a Lingua::Text object directly in strings:
  161: 
  162:     print "Hello: $greeting\n";
  163:     my $html = "<h1>" . $title . "</h1>";
  164: 
  165: You do B<not> need to call C<as_string()> yourself in most cases.
  166: 
  167: =head2 Language code format
  168: 
  169: Language codes follow ISO 639-1: two lower-case letters, e.g. C<en>, C<fr>,
  170: C<de>, C<es>, C<zh>.  An optional ISO 3166-1 country suffix may follow an
  171: underscore: C<en_US>, C<zh_CN>.  The module stores and retrieves by the
  172: two-letter code only; the country part of an environment variable is ignored
  173: during lookup.

  983: =head2 encode() cannot be undone
  984: 
  985: C<encode()> modifies the object in place.  There is no C<decode()>.  If you

  987: twice (e.g. C<&eacute;> becomes C<&amp;eacute;>).  Always call C<encode()>

  995:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode();
  996:     print $t->fr();    # &eacute;tude

 1023: 
 1024: When you pass a single string to C<new()>, it is stored under the current
 1025: system language.  If no locale environment variable (C<LANG>, C<LC_MESSAGES>,
 1026: etc.) is set, the language cannot be determined and the text is silently
 1027: discarded.
 1028: 
 1029:     # Safe: locale is set
 1030:     $ENV{LANG} = 'en_GB.UTF-8';
 1031:     my $t = Lingua::Text->new('hello');
 1032:     print $t->en();   # hello
 1033: 
 1034:     # Unsafe: no locale
 1035:     delete $ENV{LANG};
 1036:     delete $ENV{LC_MESSAGES};
 1037:     my $t = Lingua::Text->new('hello');   # text is lost
 1038:     print defined($t->en()) ? $t->en() : 'lost';   # lost
 1039: 
 1040:     # Safe alternative: always name the language explicitly
 1041:     my $t = Lingua::Text->new(en => 'hello');
 1042: 
 1043: =head2 set() and the language accessors return $self or the value, not the text
 1044: 
 1045: C<set()> returns the object (C<$self>).  Because of the stringify overload,
 1046: when you print or compare the return value, it I<looks> like a string -- but it
 1047: is an object.  Do not rely on this behaviour; retrieve the value separately.
 1048: 
 1049:     my $t = Lingua::Text->new();
 1050:     my $result = $t->set(text => 'Hello', lang => 'en');
 1051: 
 1052:     # $result is the Lingua::Text object, not the string 'Hello'
 1053:     # This works due to stringify overload, but is misleading:
 1054:     print $result;          # Hello (via stringify)
 1055: 
 1056:     # Clearer intent:
 1057:     $t->set(text => 'Hello', lang => 'en');
 1058:     print $t->as_string('en');   # Hello
 1059: 
 1060: The AUTOLOAD setter (e.g. C<$t-E<gt>en('Hello')>) returns the stored value
 1061: directly, not C<$self>.
 1062: 
 1063: =head2 A Lingua::Text object is always true
 1064: 
 1065: The object overloads the boolean C<bool> operator to always return true, even
 1066: when it contains no translations.  Do B<not> use an object as a truth test to
 1067: check whether it has any content.
 1068: 
 1069:     my $t = Lingua::Text->new();   # empty
 1070:     if($t) { print "always reached\n"; }   # always true
 1071: 
 1072:     # To check whether a specific language is stored:
 1073:     if(defined($t->en())) { print "English is stored\n"; }
 1074: 
 1075: =head2 Function-style call with arguments is an error
 1076: 
 1077: Perl allows calling methods as functions, but Lingua::Text::new() (with
 1078: double-colon and arguments) will emit a warning and return C<undef>.
 1079: 
 1080:     my $t = Lingua::Text::new(en => 'hi');   # WRONG -- carp warning, returns undef
 1081:     my $t = Lingua::Text->new(en => 'hi');   # correct
 1082: 
 1083: Calling C<Lingua::Text::new()> with B<no> arguments works (it creates an empty
 1084: object), but the arrow form is still preferred.
 1085: 
 1086: =head1 PERFORMANCE
 1087: 
 1088: Three optimisations address the hot paths in typical web or CGI use (many
 1089: objects stringified per request, same accessor called repeatedly):
 1090: 
 1091: =over 4
 1092: 
 1093: =item B<Memoised locale detection>
 1094: 
 1095: C<_get_language()> is called on every C<as_string()> invocation (including
 1096: stringify via C<"">).  The result is cached against a snapshot of the five
 1097: relevant environment variables (C<LANGUAGE>, C<LC_ALL>, C<LC_MESSAGES>,
 1098: C<LANG>, C<HTTP_ACCEPT_LANGUAGE>).  As long as those variables do not change,
 1099: subsequent calls cost only five string comparisons instead of a full
 1100: C<I18N::LangTags::Detect::detect()> scan.  The cache is invalidated
 1101: automatically when any of those variables change -- including C<local %ENV>
 1102: in tests.
 1103: 
 1104: =item B<AUTOLOAD method installation>
 1105: 
 1106: The first call to any two-letter accessor (e.g. C<$t-E<gt>en()>) installs a
 1107: real subroutine in the package symbol table.  All subsequent calls for that
 1108: code dispatch directly, bypassing the AUTOLOAD regex and guard overhead
 1109: entirely.
 1110: 
 1111: =item B<Single-argument fast path in as_string()>
 1112: 
 1113: C<$t-E<gt>as_string('en')> skips C<Params::Get::get_params()> when exactly
 1114: one non-reference argument is supplied.  Named (C<lang =E<gt> 'en'>) and
 1115: hashref (C<{ lang =E<gt> 'en' }>) forms still go through the full parser.
 1116: 
 1117: =back

 1119: =head1 LIMITATIONS
 1120: 
 1121: =over 4
 1122: 
 1123: =item * B<No decode()>: Once C<encode()> is called, all translations are
 1124: HTML-entity-encoded.  There is no method to reverse this.
 1125: 
 1126: =item * B<No language fallback>: If C<en_GB> is the system locale but only
 1127: C<en> is stored, the module finds the text correctly (because the country
 1128: suffix is stripped).  However, if C<en_GB> is stored as a key and the system
 1129: locale is C<en_US>, the text is I<not> found.  Only two-letter codes are used
 1130: as storage keys.
 1131: 
 1132: =item * B<Silent AUTOLOAD failures>: Unrecognised method names (including
 1133: typos) return C<undef> without any diagnostic.
 1134: 
 1135: =item * B<Object::Configure semantics>: The exact effect of
 1136: L<Object::Configure> depends on the installed version and any project-level
 1137: configuration present.  Without a configuration file, it passes parameters
 1138: through unchanged.
