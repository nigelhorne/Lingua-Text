  122: =head1 DESCRIPTION
  123: 
  124: Lingua::Text is a simple container that stores the same piece of text in
  125: multiple languages inside a single Perl object.  When you ask the object to
  126: print itself (or convert to a string), it automatically reads the user's
  127: operating-system language setting and returns the correct translation.
  128: 
  129: =head2 How language detection works
  130: 
  131: The module reads the following environment variables, in this order, and uses
  132: the first one it finds that contains a two-letter language code:
  133: 
  134: =over 4
  135: 
  136: =item 1. C<LANGUAGE> (space- or colon-separated preference list, e.g. C<fr:en>)
  137: 
  138: =item 2. C<LC_ALL>
  139: 
  140: =item 3. C<LC_MESSAGES>
  141: 
  142: =item 4. C<LANG> (e.g. C<en_US.UTF-8> or C<de_DE>)
  143: 
  144: =back
  145: 
  146: In CGI or web environments, C<I18N::LangTags::Detect> also inspects the
  147: C<HTTP_ACCEPT_LANGUAGE> request header (when available in the environment)
  148: before falling back to the variables above.  The memoisation cache tracks
  149: this variable alongside the four above, so the cache is invalidated
  150: correctly when the header changes between requests.
  151: 
  152: Only the first two letters are used (e.g. C<en_GB.UTF-8> becomes C<en>), so
  153: you only need to store one translation per language, not per locale variant.
  154: 
  155: If none of these variables is set, or if C<LANG> is set to the POSIX C<C>
  156: or C<C.UTF-8> locale, the module returns C<undef> (or C<'en'> for the C
  157: locale).
  158: 
  159: =head2 How string interpolation works
  160: 
  161: The object overloads Perl's C<""> (stringify) operator.  This means you can
  162: use a Lingua::Text object directly in strings:
  163: 
  164:     print "Hello: $greeting\n";
  165:     my $html = "<h1>" . $title . "</h1>";
  166: 
  167: You do B<not> need to call C<as_string()> yourself in most cases.
  168: 
  169: =head2 Language code format
  170: 
  171: Language codes follow ISO 639-1: two lower-case letters, e.g. C<en>, C<fr>,
  172: C<de>, C<es>, C<zh>.  An optional ISO 3166-1 country suffix may follow an
  173: underscore: C<en_US>, C<zh_CN>.  The module stores and retrieves by the
  174: two-letter code only; the country part of an environment variable is ignored
  175: during lookup.

 1023:     print $t->enn();    # undef -- no warning, no error
 1024: 
 1025: To guard against this, always check with C<defined()> and, during development,
 1026: consider adding a test that verifies the expected languages are present.
 1027: 
 1028: =head2 new('text') silently drops the text when no locale is set
 1029: 
 1030: When you pass a single string to C<new()>, it is stored under the current
 1031: system language.  If no locale environment variable (C<LANG>, C<LC_MESSAGES>,
 1032: etc.) is set, the language cannot be determined and the text is silently
 1033: discarded.
 1034: 
 1035:     # Safe: locale is set
 1036:     $ENV{LANG} = 'en_GB.UTF-8';
 1037:     my $t = Lingua::Text->new('hello');
 1038:     print $t->en();   # hello
 1039: 
 1040:     # Unsafe: no locale
 1041:     delete $ENV{LANG};
 1042:     delete $ENV{LC_MESSAGES};
 1043:     my $t = Lingua::Text->new('hello');   # text is lost
 1044:     print defined($t->en()) ? $t->en() : 'lost';   # lost
 1045: 
 1046:     # Safe alternative: always name the language explicitly
 1047:     my $t = Lingua::Text->new(en => 'hello');
 1048: 
 1049: =head2 set() and the language accessors return $self or the value, not the text
 1050: 
 1051: C<set()> returns the object (C<$self>).  Because of the stringify overload,
 1052: when you print or compare the return value, it I<looks> like a string -- but it
 1053: is an object.  Do not rely on this behaviour; retrieve the value separately.
 1054: 
 1055:     my $t = Lingua::Text->new();
 1056:     my $result = $t->set(text => 'Hello', lang => 'en');
 1057: 
 1058:     # $result is the Lingua::Text object, not the string 'Hello'
 1059:     # This works due to stringify overload, but is misleading:
 1060:     print $result;          # Hello (via stringify)
 1061: 
 1062:     # Clearer intent:
 1063:     $t->set(text => 'Hello', lang => 'en');
 1064:     print $t->as_string('en');   # Hello
 1065: 
 1066: The AUTOLOAD setter (e.g. C<$t-E<gt>en('Hello')>) returns the stored value
 1067: directly, not C<$self>.
 1068: 
 1069: =head2 A Lingua::Text object is always true
 1070: 
 1071: The object overloads the boolean C<bool> operator to always return true, even
 1072: when it contains no translations.  Do B<not> use an object as a truth test to
 1073: check whether it has any content.
 1074: 
 1075:     my $t = Lingua::Text->new();   # empty
 1076:     if($t) { print "always reached\n"; }   # always true
 1077: 
 1078:     # To check whether a specific language is stored:
 1079:     if(defined($t->en())) { print "English is stored\n"; }
 1080: 
 1081: =head2 Function-style call with arguments is an error
 1082: 
 1083: Perl allows calling methods as functions, but Lingua::Text::new() (with
 1084: double-colon and arguments) will emit a warning and return C<undef>.
 1085: 
 1086:     my $t = Lingua::Text::new(en => 'hi');   # WRONG -- carp warning, returns undef
 1087:     my $t = Lingua::Text->new(en => 'hi');   # correct
 1088: 
 1089: Calling C<Lingua::Text::new()> with B<no> arguments works (it creates an empty
 1090: object), but the arrow form is still preferred.
 1091: 
 1092: =head1 PERFORMANCE
 1093: 
 1094: Three optimisations address the hot paths in typical web or CGI use (many
 1095: objects stringified per request, same accessor called repeatedly):
 1096: 
 1097: =over 4
 1098: 
 1099: =item B<Memoised locale detection>
 1100: 
 1101: C<_get_language()> is called on every C<as_string()> invocation (including
 1102: stringify via C<"">).  The result is cached against a snapshot of the five
 1103: relevant environment variables (C<LANGUAGE>, C<LC_ALL>, C<LC_MESSAGES>,
 1104: C<LANG>, C<HTTP_ACCEPT_LANGUAGE>).  As long as those variables do not change,
 1105: subsequent calls cost only five string comparisons instead of a full
 1106: C<I18N::LangTags::Detect::detect()> scan.  The cache is invalidated
 1107: automatically when any of those variables change -- including C<local %ENV>
 1108: in tests.
 1109: 
 1110: =item B<AUTOLOAD method installation>
 1111: 
 1112: The first call to any two-letter accessor (e.g. C<$t-E<gt>en()>) installs a
 1113: real subroutine in the package symbol table.  All subsequent calls for that
 1114: code dispatch directly, bypassing the AUTOLOAD regex and guard overhead
 1115: entirely.
 1116: 
 1117: =item B<Single-argument fast path in as_string()>
 1118: 
 1119: C<$t-E<gt>as_string('en')> skips C<Params::Get::get_params()> when exactly
 1120: one non-reference argument is supplied.  Named (C<lang =E<gt> 'en'>) and
 1121: hashref (C<{ lang =E<gt> 'en' }>) forms still go through the full parser.
 1122: 
 1123: =back
 1124: 
 1125: =head1 LIMITATIONS
 1126: 
 1127: =over 4
 1128: 
 1129: =item * B<No decode()>: Once C<encode()> is called, all translations are
 1130: HTML-entity-encoded.  There is no method to reverse this.
 1131: 
 1132: =item * B<No language fallback>: If C<en_GB> is the system locale but only
 1133: C<en> is stored, the module finds the text correctly (because the country
 1134: suffix is stripped).  However, if C<en_GB> is stored as a key and the system
 1135: locale is C<en_US>, the text is I<not> found.  Only two-letter codes are used
 1136: as storage keys.
 1137: 
 1138: =item * B<Silent AUTOLOAD failures>: Unrecognised method names (including
 1139: typos) return C<undef> without any diagnostic.
 1140: 
 1141: =item * B<Object::Configure semantics>: The exact effect of
 1142: L<Object::Configure> depends on the installed version and any project-level
 1143: configuration present.  Without a configuration file, it passes parameters
 1144: through unchanged.
