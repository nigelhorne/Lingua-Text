  160:     print $name;   # prints in the user's system language

  187: =head1 DESCRIPTION
  188: 
  189: Lingua::Text is a simple container that stores the same piece of text in
  190: multiple languages inside a single Perl object.  When you ask the object to
  191: print itself (or convert to a string), it automatically reads the user's
  192: operating-system language setting and returns the correct translation.
  193: 
  194: =head2 How language detection works
  195: 
  196: The module reads the following environment variables, in this order, and uses
  197: the first one it finds that contains a two-letter language code:
  198: 
  199: =over 4
  200: 
  201: =item 1. C<LANGUAGE> (space- or colon-separated preference list, e.g. C<fr:en>)
  202: 
  203: =item 2. C<LC_ALL>
  204: 
  205: =item 3. C<LC_MESSAGES>
  206: 
  207: =item 4. C<LANG> (e.g. C<en_US.UTF-8> or C<de_DE>)
  208: 
  209: =back
  210: 
  211: Only the first two letters are used (e.g. C<en_GB.UTF-8> becomes C<en>), so
  212: you only need to store one translation per language, not per locale variant.
  213: 
  214: If none of these variables is set, or if C<LANG> is set to the POSIX C<C>
  215: or C<C.UTF-8> locale, the module returns C<undef> (or C<'en'> for the C
  216: locale).
  217: 
  218: =head2 How string interpolation works
  219: 
  220: The object overloads Perl's C<""> (stringify) operator.  This means you can
  221: use a Lingua::Text object directly in strings:
  222: 
  223:     print "Hello: $greeting\n";
  224:     my $html = "<h1>" . $title . "</h1>";
  225: 
  226: You do B<not> need to call C<as_string()> yourself in most cases.
  227: 
  228: =head2 Language code format
  229: 
  230: Language codes follow ISO 639-1: two lower-case letters, e.g. C<en>, C<fr>,
  231: C<de>, C<es>, C<zh>.  An optional ISO 3166-1 country suffix may follow an
  232: underscore: C<en_US>, C<zh_CN>.  The module stores and retrieves by the
  233: two-letter code only; the country part of an environment variable is ignored
  234: during lookup.

  240: =head3 PURPOSE
  241: 
  242: Create a new Lingua::Text object.  The object starts empty, or pre-loaded
  243: with one or more translations you provide.
  244: 
  245: Calling C<new()> on an B<existing> object creates an independent copy (a

  247: is never modified.
  248: 
  249: =head3 ARGUMENTS
  250: 
  251: You may pass arguments in any of the following forms:
  252: 
  253: =over 4
  254: 
  255: =item No arguments -- creates an empty object
  256: 
  257:     my $t = Lingua::Text->new();
  258: 
  259: =item Key/value pairs -- one pair per language
  260: 
  261:     my $t = Lingua::Text->new(en => 'boat', fr => 'bateau');
  262: 
  263: =item A hash reference
  264: 
  265:     my $t = Lingua::Text->new({ en => 'boat', fr => 'bateau' });
  266: 
  267: =item A single plain string -- stored under the current system locale language
  268: 
  269:     # Only works if a locale environment variable is set.
  270:     # If no locale is set, the text is silently discarded.  See COMMON PITFALLS.
  271:     my $t = Lingua::Text->new('hello');
  272: 
  273: =item An existing Lingua::Text object -- creates a clone
  274: 
  275:     my $clone = $original->new();                      # exact copy
  276:     my $clone = $original->new(de => 'zusatz');        # copy + one more language
  277: 
  278: =back
  279: 
  280: =head3 RETURN VALUE
  281: 
  282: Returns a blessed Lingua::Text reference on success.
  283: 
  284: Returns C<undef> and emits a C<carp> warning when called as a plain function

  286:

  847: =head2 encode() cannot be undone
  848: 
  849: C<encode()> modifies the object in place.  There is no C<decode()>.  If you
  850: call C<encode()> twice on the same object, every special character is encoded
  851: twice (e.g. C<&eacute;> becomes C<&amp;eacute;>).  Always call C<encode()>
  852: once, as the last step, and only on a freshly built object.
  853: 
  854:     # WRONG -- double-encoding
  855:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode()->encode();
  856:     print $t->fr();    # &amp;eacute;tude  (broken HTML)
  857: 
  858:     # CORRECT
  859:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode();
  860:     print $t->fr();    # &eacute;tude
  861: 
  862: =head2 Missing translation returns undef, not an empty string
  863: 
  864: When a translation is not stored for the requested language, C<as_string()>
  865: and the accessor methods return C<undef>, not C<"">.  Use C<defined()> to test
  866: for absence, not a truth check.
  867: 
  868:     my $t = Lingua::Text->new(en => 'hello');
  869: 
  870:     my $de = $t->de();
  871:     print "Missing\n" unless defined($de);   # correct
  872:     print "Missing\n" unless $de;            # WRONG -- also triggers for $de = '0'
  873: 
  874: =head2 Typos in language codes are silent
  875: 
  876: The AUTOLOAD accessor returns C<undef> for any two-letter name that is not a
  877: valid ISO 639-1 code, and also for valid codes that have no stored translation.
  878: A typo like C<$t-E<gt>enn()> produces C<undef> without any warning.
  879: 
  880:     $t->en('hello');
  881:     print $t->enn();    # undef -- no warning, no error
  882: 
  883: To guard against this, always check with C<defined()> and, during development,
  884: consider adding a test that verifies the expected languages are present.
  885: 
  886: =head2 new('text') silently drops the text when no locale is set
  887: 
  888: When you pass a single string to C<new()>, it is stored under the current
  889: system language.  If no locale environment variable (C<LANG>, C<LC_MESSAGES>,
  890: etc.) is set, the language cannot be determined and the text is silently
  891: discarded.
  892: 
  893:     # Safe: locale is set
  894:     $ENV{LANG} = 'en_GB.UTF-8';
  895:     my $t = Lingua::Text->new('hello');
  896:     print $t->en();   # hello
  897: 
  898:     # Unsafe: no locale
  899:     delete $ENV{LANG};
  900:     delete $ENV{LC_MESSAGES};
  901:     my $t = Lingua::Text->new('hello');   # text is lost
  902:     print defined($t->en()) ? $t->en() : 'lost';   # lost
  903: 
  904:     # Safe alternative: always name the language explicitly
  905:     my $t = Lingua::Text->new(en => 'hello');
  906: 
  907: =head2 set() and the language accessors return $self or the value, not the text
  908: 
  909: C<set()> returns the object (C<$self>).  Because of the stringify overload,
  910: when you print or compare the return value, it I<looks> like a string -- but it
  911: is an object.  Do not rely on this behaviour; retrieve the value separately.
  912: 
  913:     my $t = Lingua::Text->new();
  914:     my $result = $t->set(text => 'Hello', lang => 'en');
  915: 
  916:     # $result is the Lingua::Text object, not the string 'Hello'
  917:     # This works due to stringify overload, but is misleading:
  918:     print $result;          # Hello (via stringify)
  919: 
  920:     # Clearer intent:
  921:     $t->set(text => 'Hello', lang => 'en');
  922:     print $t->as_string('en');   # Hello
  923: 
  924: The AUTOLOAD setter (e.g. C<$t-E<gt>en('Hello')>) returns the stored value
  925: directly, not C<$self>.
  926: 
  927: =head2 A Lingua::Text object is always true
  928: 
  929: The object overloads the boolean C<bool> operator to always return true, even
  930: when it contains no translations.  Do B<not> use an object as a truth test to
  931: check whether it has any content.
  932: 
  933:     my $t = Lingua::Text->new();   # empty
  934:     if($t) { print "always reached\n"; }   # always true
  935: 
  936:     # To check whether a specific language is stored:
  937:     if(defined($t->en())) { print "English is stored\n"; }
  938: 
  939: =head2 Function-style call with arguments is an error
  940: 
  941: Perl allows calling methods as functions, but Lingua::Text::new() (with
  942: double-colon and arguments) will emit a warning and return C<undef>.
  943: 
  944:     my $t = Lingua::Text::new(en => 'hi');   # WRONG -- carp warning, returns undef
  945:     my $t = Lingua::Text->new(en => 'hi');   # correct
  946: 
  947: Calling C<Lingua::Text::new()> with B<no> arguments works (it creates an empty
  948: object), but the arrow form is still preferred.
  949: 
  950: =head1 LIMITATIONS
  951: 
  952: =over 4
  953: 
  954: =item * B<No decode()>: Once C<encode()> is called, all translations are
  955: HTML-entity-encoded.  There is no method to reverse this.
  956: 
  957: =item * B<No language fallback>: If C<en_GB> is the system locale but only
  958: C<en> is stored, the module finds the text correctly (because the country
  959: suffix is stripped).  However, if C<en_GB> is stored as a key and the system
  960: locale is C<en_US>, the text is I<not> found.  Only two-letter codes are used
  961: as storage keys.
  962: 
  963: =item * B<Silent AUTOLOAD failures>: Unrecognised method names (including
  964: typos) return C<undef> without any diagnostic.
  965: 
  966: =item * B<Object::Configure semantics>: The exact effect of
  967: L<Object::Configure> depends on the installed version and any project-level
  968: configuration present.  Without a configuration file, it passes parameters
  969: through unchanged.
  970: 
  971: =back
