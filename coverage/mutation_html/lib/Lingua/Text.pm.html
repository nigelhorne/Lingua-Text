  128: =head1 DESCRIPTION
  129: 
  130: Lingua::Text is a simple container that stores the same piece of text in
  131: multiple languages inside a single Perl object.  When you ask the object to
  132: print itself (or convert to a string), it automatically reads the user's
  133: operating-system language setting and returns the correct translation.
  134: 
  135: =head2 How language detection works
  136: 
  137: The module reads the following environment variables, in this order, and uses
  138: the first one it finds that contains a two-letter language code:
  139: 
  140: =over 4
  141: 
  142: =item 1. C<LANGUAGE> (space- or colon-separated preference list, e.g. C<fr:en>)
  143: 
  144: =item 2. C<LC_ALL>
  145: 
  146: =item 3. C<LC_MESSAGES>
  147: 
  148: =item 4. C<LANG> (e.g. C<en_US.UTF-8> or C<de_DE>)
  149: 
  150: =back
  151: 
  152: Only the first two letters are used (e.g. C<en_GB.UTF-8> becomes C<en>), so
  153: you only need to store one translation per language, not per locale variant.
  154: 
  155: If none of these variables is set, or if C<LANG> is set to the POSIX C<C>
  156: or C<C.UTF-8> locale, the module returns C<undef> (or C<'en'> for the C
  157: locale).
  158: 
  159: =head2 How string interpolation works
  160: 
  161: The object overloads Perl's C<""> (stringify) operator.  This means you can
  162: use a Lingua::Text object directly in strings:
  163: 
  164:     print "Hello: $greeting\n";
  165:     my $html = "<h1>" . $title . "</h1>";
  166: 
  167: You do B<not> need to call C<as_string()> yourself in most cases.
  168: 
  169: =head2 Language code format
  170: 
  171: Language codes follow ISO 639-1: two lower-case letters, e.g. C<en>, C<fr>,
  172: C<de>, C<es>, C<zh>.  An optional ISO 3166-1 country suffix may follow an
  173: underscore: C<en_US>, C<zh_CN>.  The module stores and retrieves by the
  174: two-letter code only; the country part of an environment variable is ignored
  175: during lookup.

  355: =head3 PURPOSE
  356: 
  357: Store or replace a single translation.  Use this when the language code is
  358: held in a variable at runtime; if the language is fixed at coding time, the
  359: shorthand accessor (e.g. C<$t-E<gt>en('Hello')>) is simpler.
  360: 
  361: =head3 ARGUMENTS
  362: 
  363:     text  -- the translation string (required)
  364:     lang  -- two-letter language code (optional; defaults to the system locale)
  365: 
  366: The arguments may be passed as a hash, a hash reference, or as a plain
  367: positional string (only C<text>; C<lang> then comes from the system locale).
  368: 
  369: =head3 RETURN VALUE
  370:

  374: not the string.  See L</COMMON PITFALLS>.

  901: =head1 COMMON PITFALLS
  902: 
  903: This section documents behaviours that often surprise first-time users.
  904: 
  905: =head2 encode() cannot be undone
  906: 
  907: C<encode()> modifies the object in place.  There is no C<decode()>.  If you
  908: call C<encode()> twice on the same object, every special character is encoded
  909: twice (e.g. C<&eacute;> becomes C<&amp;eacute;>).  Always call C<encode()>
  910: once, as the last step, and only on a freshly built object.
  911: 
  912:     # WRONG -- double-encoding
  913:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode()->encode();
  914:     print $t->fr();    # &amp;eacute;tude  (broken HTML)
  915: 
  916:     # CORRECT
  917:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode();
  918:     print $t->fr();    # &eacute;tude
  919: 
  920: =head2 Missing translation returns undef, not an empty string
  921: 
  922: When a translation is not stored for the requested language, C<as_string()>
  923: and the accessor methods return C<undef>, not C<"">.  Use C<defined()> to test
  924: for absence, not a truth check.
  925: 
  926:     my $t = Lingua::Text->new(en => 'hello');
  927: 
  928:     my $de = $t->de();
  929:     print "Missing\n" unless defined($de);   # correct
  930:     print "Missing\n" unless $de;            # WRONG -- also triggers for $de = '0'
  931: 
  932: =head2 Typos in language codes are silent
  933: 
  934: The AUTOLOAD accessor returns C<undef> for any two-letter name that is not a
  935: valid ISO 639-1 code, and also for valid codes that have no stored translation.
  936: A typo like C<$t-E<gt>enn()> produces C<undef> without any warning.
  937: 
  938:     $t->en('hello');
  939:     print $t->enn();    # undef -- no warning, no error
  940: 
  941: To guard against this, always check with C<defined()> and, during development,
  942: consider adding a test that verifies the expected languages are present.
  943: 
  944: =head2 new('text') silently drops the text when no locale is set
  945: 
  946: When you pass a single string to C<new()>, it is stored under the current
  947: system language.  If no locale environment variable (C<LANG>, C<LC_MESSAGES>,
  948: etc.) is set, the language cannot be determined and the text is silently
  949: discarded.
  950: 
  951:     # Safe: locale is set
  952:     $ENV{LANG} = 'en_GB.UTF-8';
  953:     my $t = Lingua::Text->new('hello');
  954:     print $t->en();   # hello
  955: 
  956:     # Unsafe: no locale
  957:     delete $ENV{LANG};
  958:     delete $ENV{LC_MESSAGES};
  959:     my $t = Lingua::Text->new('hello');   # text is lost
  960:     print defined($t->en()) ? $t->en() : 'lost';   # lost
  961: 
  962:     # Safe alternative: always name the language explicitly
  963:     my $t = Lingua::Text->new(en => 'hello');
  964: 
  965: =head2 set() and the language accessors return $self or the value, not the text
  966: 
  967: C<set()> returns the object (C<$self>).  Because of the stringify overload,
  968: when you print or compare the return value, it I<looks> like a string -- but it
  969: is an object.  Do not rely on this behaviour; retrieve the value separately.
  970: 
  971:     my $t = Lingua::Text->new();
  972:     my $result = $t->set(text => 'Hello', lang => 'en');
  973: 
  974:     # $result is the Lingua::Text object, not the string 'Hello'
  975:     # This works due to stringify overload, but is misleading:
  976:     print $result;          # Hello (via stringify)
  977: 
  978:     # Clearer intent:
  979:     $t->set(text => 'Hello', lang => 'en');
  980:     print $t->as_string('en');   # Hello
  981: 
  982: The AUTOLOAD setter (e.g. C<$t-E<gt>en('Hello')>) returns the stored value
  983: directly, not C<$self>.
  984: 
  985: =head2 A Lingua::Text object is always true
  986: 
  987: The object overloads the boolean C<bool> operator to always return true, even
  988: when it contains no translations.  Do B<not> use an object as a truth test to
  989: check whether it has any content.
  990: 
  991:     my $t = Lingua::Text->new();   # empty
  992:     if($t) { print "always reached\n"; }   # always true
  993: 
  994:     # To check whether a specific language is stored:
  995:     if(defined($t->en())) { print "English is stored\n"; }
  996: 
  997: =head2 Function-style call with arguments is an error
  998: 
  999: Perl allows calling methods as functions, but Lingua::Text::new() (with
 1000: double-colon and arguments) will emit a warning and return C<undef>.
 1001: 
 1002:     my $t = Lingua::Text::new(en => 'hi');   # WRONG -- carp warning, returns undef
 1003:     my $t = Lingua::Text->new(en => 'hi');   # correct
 1004: 
 1005: Calling C<Lingua::Text::new()> with B<no> arguments works (it creates an empty
 1006: object), but the arrow form is still preferred.
 1007: 
 1008: =head1 PERFORMANCE
 1009: 
 1010: Three optimisations address the hot paths in typical web or CGI use (many
 1011: objects stringified per request, same accessor called repeatedly):
 1012: 
 1013: =over 4
 1014: 
 1015: =item B<Memoised locale detection>
 1016: 
 1017: C<_get_language()> is called on every C<as_string()> invocation (including
 1018: stringify via C<"">).  The result is cached against a snapshot of the five
 1019: relevant environment variables (C<LANGUAGE>, C<LC_ALL>, C<LC_MESSAGES>,
 1020: C<LANG>, C<HTTP_ACCEPT_LANGUAGE>).  As long as those variables do not change,
 1021: subsequent calls cost only five string comparisons instead of a full
 1022: C<I18N::LangTags::Detect::detect()> scan.  The cache is invalidated
 1023: automatically when any of those variables change -- including C<local %ENV>
 1024: in tests.
 1025: 
 1026: =item B<AUTOLOAD method installation>
 1027: 
 1028: The first call to any two-letter accessor (e.g. C<$t-E<gt>en()>) installs a
 1029: real subroutine in the package symbol table.  All subsequent calls for that
 1030: code dispatch directly, bypassing the AUTOLOAD regex and guard overhead
 1031: entirely.
 1032: 
 1033: =item B<Single-argument fast path in as_string()>
 1034: 
 1035: C<$t-E<gt>as_string('en')> skips C<Params::Get::get_params()> when exactly
 1036: one non-reference argument is supplied.  Named (C<lang =E<gt> 'en'>) and
 1037: hashref (C<{ lang =E<gt> 'en' }>) forms still go through the full parser.
 1038: 
 1039: =back

 1041: =head1 LIMITATIONS
 1042: 
 1043: =over 4
 1044: 
 1045: =item * B<No decode()>: Once C<encode()> is called, all translations are
 1046: HTML-entity-encoded.  There is no method to reverse this.
 1047: 
 1048: =item * B<No language fallback>: If C<en_GB> is the system locale but only
 1049: C<en> is stored, the module finds the text correctly (because the country
 1050: suffix is stripped).  However, if C<en_GB> is stored as a key and the system
 1051: locale is C<en_US>, the text is I<not> found.  Only two-letter codes are used
 1052: as storage keys.
 1053: 
 1054: =item * B<Silent AUTOLOAD failures>: Unrecognised method names (including
 1055: typos) return C<undef> without any diagnostic.
 1056: 
 1057: =item * B<Object::Configure semantics>: The exact effect of
 1058: L<Object::Configure> depends on the installed version and any project-level
 1059: configuration present.  Without a configuration file, it passes parameters
 1060: through unchanged.
 1061:
