  126: =head1 DESCRIPTION
  127: 
  128: Lingua::Text is a simple container that stores the same piece of text in
  129: multiple languages inside a single Perl object.  When you ask the object to
  130: print itself (or convert to a string), it automatically reads the user's
  131: operating-system language setting and returns the correct translation.
  132: 
  133: =head2 How language detection works
  134: 
  135: The module reads the following environment variables, in this order, and uses
  136: the first one it finds that contains a two-letter language code:
  137: 
  138: =over 4
  139: 
  140: =item 1. C<LANGUAGE> (space- or colon-separated preference list, e.g. C<fr:en>)
  141: 
  142: =item 2. C<LC_ALL>
  143: 
  144: =item 3. C<LC_MESSAGES>
  145: 
  146: =item 4. C<LANG> (e.g. C<en_US.UTF-8> or C<de_DE>)
  147: 
  148: =back
  149: 
  150: Only the first two letters are used (e.g. C<en_GB.UTF-8> becomes C<en>), so
  151: you only need to store one translation per language, not per locale variant.
  152: 
  153: If none of these variables is set, or if C<LANG> is set to the POSIX C<C>
  154: or C<C.UTF-8> locale, the module returns C<undef> (or C<'en'> for the C
  155: locale).
  156: 
  157: =head2 How string interpolation works
  158: 
  159: The object overloads Perl's C<""> (stringify) operator.  This means you can
  160: use a Lingua::Text object directly in strings:
  161: 
  162:     print "Hello: $greeting\n";
  163:     my $html = "<h1>" . $title . "</h1>";
  164: 
  165: You do B<not> need to call C<as_string()> yourself in most cases.
  166: 
  167: =head2 Language code format
  168: 
  169: Language codes follow ISO 639-1: two lower-case letters, e.g. C<en>, C<fr>,
  170: C<de>, C<es>, C<zh>.  An optional ISO 3166-1 country suffix may follow an
  171: underscore: C<en_US>, C<zh_CN>.  The module stores and retrieves by the
  172: two-letter code only; the country part of an environment variable is ignored
  173: during lookup.

  844: =head1 COMMON PITFALLS
  845: 
  846: This section documents behaviours that often surprise first-time users.
  847: 
  848: =head2 encode() cannot be undone
  849: 
  850: C<encode()> modifies the object in place.  There is no C<decode()>.  If you
  851: call C<encode()> twice on the same object, every special character is encoded
  852: twice (e.g. C<&eacute;> becomes C<&amp;eacute;>).  Always call C<encode()>
  853: once, as the last step, and only on a freshly built object.
  854: 
  855:     # WRONG -- double-encoding
  856:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode()->encode();
  857:     print $t->fr();    # &amp;eacute;tude  (broken HTML)
  858: 
  859:     # CORRECT
  860:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode();
  861:     print $t->fr();    # &eacute;tude
  862: 
  863: =head2 Missing translation returns undef, not an empty string
  864: 
  865: When a translation is not stored for the requested language, C<as_string()>
  866: and the accessor methods return C<undef>, not C<"">.  Use C<defined()> to test
  867: for absence, not a truth check.
  868: 
  869:     my $t = Lingua::Text->new(en => 'hello');
  870: 
  871:     my $de = $t->de();
  872:     print "Missing\n" unless defined($de);   # correct
  873:     print "Missing\n" unless $de;            # WRONG -- also triggers for $de = '0'
  874: 
  875: =head2 Typos in language codes are silent
  876: 
  877: The AUTOLOAD accessor returns C<undef> for any two-letter name that is not a
  878: valid ISO 639-1 code, and also for valid codes that have no stored translation.
  879: A typo like C<$t-E<gt>enn()> produces C<undef> without any warning.
  880: 
  881:     $t->en('hello');
  882:     print $t->enn();    # undef -- no warning, no error
  883: 
  884: To guard against this, always check with C<defined()> and, during development,
  885: consider adding a test that verifies the expected languages are present.
  886: 
  887: =head2 new('text') silently drops the text when no locale is set
  888: 
  889: When you pass a single string to C<new()>, it is stored under the current
  890: system language.  If no locale environment variable (C<LANG>, C<LC_MESSAGES>,
  891: etc.) is set, the language cannot be determined and the text is silently
  892: discarded.
  893: 
  894:     # Safe: locale is set
  895:     $ENV{LANG} = 'en_GB.UTF-8';
  896:     my $t = Lingua::Text->new('hello');
  897:     print $t->en();   # hello
  898: 
  899:     # Unsafe: no locale
  900:     delete $ENV{LANG};
  901:     delete $ENV{LC_MESSAGES};
  902:     my $t = Lingua::Text->new('hello');   # text is lost
  903:     print defined($t->en()) ? $t->en() : 'lost';   # lost
  904: 
  905:     # Safe alternative: always name the language explicitly
  906:     my $t = Lingua::Text->new(en => 'hello');
  907: 
  908: =head2 set() and the language accessors return $self or the value, not the text
  909: 
  910: C<set()> returns the object (C<$self>).  Because of the stringify overload,
  911: when you print or compare the return value, it I<looks> like a string -- but it
  912: is an object.  Do not rely on this behaviour; retrieve the value separately.
  913: 
  914:     my $t = Lingua::Text->new();
  915:     my $result = $t->set(text => 'Hello', lang => 'en');
  916: 
  917:     # $result is the Lingua::Text object, not the string 'Hello'
  918:     # This works due to stringify overload, but is misleading:
  919:     print $result;          # Hello (via stringify)
  920: 
  921:     # Clearer intent:
  922:     $t->set(text => 'Hello', lang => 'en');
  923:     print $t->as_string('en');   # Hello
  924: 
  925: The AUTOLOAD setter (e.g. C<$t-E<gt>en('Hello')>) returns the stored value
  926: directly, not C<$self>.
  927: 
  928: =head2 A Lingua::Text object is always true
  929: 
  930: The object overloads the boolean C<bool> operator to always return true, even
  931: when it contains no translations.  Do B<not> use an object as a truth test to
  932: check whether it has any content.
  933: 
  934:     my $t = Lingua::Text->new();   # empty
  935:     if($t) { print "always reached\n"; }   # always true
  936: 
  937:     # To check whether a specific language is stored:
  938:     if(defined($t->en())) { print "English is stored\n"; }
  939: 
  940: =head2 Function-style call with arguments is an error
  941: 
  942: Perl allows calling methods as functions, but Lingua::Text::new() (with
  943: double-colon and arguments) will emit a warning and return C<undef>.
  944: 
  945:     my $t = Lingua::Text::new(en => 'hi');   # WRONG -- carp warning, returns undef
  946:     my $t = Lingua::Text->new(en => 'hi');   # correct
  947: 
  948: Calling C<Lingua::Text::new()> with B<no> arguments works (it creates an empty
  949: object), but the arrow form is still preferred.

  951: =head1 PERFORMANCE
  952: 
  953: Three optimisations address the hot paths in typical web or CGI use (many
  954: objects stringified per request, same accessor called repeatedly):
  955: 
  956: =over 4
  957: 
  958: =item B<Memoised locale detection>
  959: 
  960: C<_get_language()> is called on every C<as_string()> invocation (including
  961: stringify via C<"">).  The result is cached against a snapshot of the five
  962: relevant environment variables (C<LANGUAGE>, C<LC_ALL>, C<LC_MESSAGES>,
  963: C<LANG>, C<HTTP_ACCEPT_LANGUAGE>).  As long as those variables do not change,
  964: subsequent calls cost only five string comparisons instead of a full
  965: C<I18N::LangTags::Detect::detect()> scan.  The cache is invalidated
  966: automatically when any of those variables change -- including C<local %ENV>
  967: in tests.
  968: 
  969: =item B<AUTOLOAD method installation>
  970: 
  971: The first call to any two-letter accessor (e.g. C<$t-E<gt>en()>) installs a
  972: real subroutine in the package symbol table.  All subsequent calls for that
  973: code dispatch directly, bypassing the AUTOLOAD regex and guard overhead
  974: entirely.
  975: 
  976: =item B<Single-argument fast path in as_string()>
  977: 
  978: C<$t-E<gt>as_string('en')> skips C<Params::Get::get_params()> when exactly
  979: one non-reference argument is supplied.  Named (C<lang =E<gt> 'en'>) and
  980: hashref (C<{ lang =E<gt> 'en' }>) forms still go through the full parser.
  981: 
  982: =back

  991: =item * B<No language fallback>: If C<en_GB> is the system locale but only

  995: as storage keys.
