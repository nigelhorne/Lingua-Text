  126: =head1 DESCRIPTION
  127: 
  128: Lingua::Text is a simple container that stores the same piece of text in
  129: multiple languages inside a single Perl object.  When you ask the object to
  130: print itself (or convert to a string), it automatically reads the user's
  131: operating-system language setting and returns the correct translation.
  132: 
  133: =head2 How language detection works
  134: 
  135: The module reads the following environment variables, in this order, and uses
  136: the first one it finds that contains a two-letter language code:
  137: 
  138: =over 4
  139: 
  140: =item 1. C<LANGUAGE> (space- or colon-separated preference list, e.g. C<fr:en>)
  141: 
  142: =item 2. C<LC_ALL>
  143: 
  144: =item 3. C<LC_MESSAGES>
  145: 
  146: =item 4. C<LANG> (e.g. C<en_US.UTF-8> or C<de_DE>)
  147: 
  148: =back
  149: 
  150: Only the first two letters are used (e.g. C<en_GB.UTF-8> becomes C<en>), so
  151: you only need to store one translation per language, not per locale variant.
  152: 
  153: If none of these variables is set, or if C<LANG> is set to the POSIX C<C>
  154: or C<C.UTF-8> locale, the module returns C<undef> (or C<'en'> for the C
  155: locale).
  156: 
  157: =head2 How string interpolation works
  158: 
  159: The object overloads Perl's C<""> (stringify) operator.  This means you can
  160: use a Lingua::Text object directly in strings:
  161: 
  162:     print "Hello: $greeting\n";
  163:     my $html = "<h1>" . $title . "</h1>";
  164: 
  165: You do B<not> need to call C<as_string()> yourself in most cases.
  166: 
  167: =head2 Language code format
  168: 
  169: Language codes follow ISO 639-1: two lower-case letters, e.g. C<en>, C<fr>,
  170: C<de>, C<es>, C<zh>.  An optional ISO 3166-1 country suffix may follow an
  171: underscore: C<en_US>, C<zh_CN>.  The module stores and retrieves by the
  172: two-letter code only; the country part of an environment variable is ignored
  173: during lookup.

  850: =head1 COMMON PITFALLS
  851: 
  852: This section documents behaviours that often surprise first-time users.
  853: 
  854: =head2 encode() cannot be undone
  855: 
  856: C<encode()> modifies the object in place.  There is no C<decode()>.  If you
  857: call C<encode()> twice on the same object, every special character is encoded
  858: twice (e.g. C<&eacute;> becomes C<&amp;eacute;>).  Always call C<encode()>
  859: once, as the last step, and only on a freshly built object.
  860: 
  861:     # WRONG -- double-encoding
  862:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode()->encode();
  863:     print $t->fr();    # &amp;eacute;tude  (broken HTML)
  864: 
  865:     # CORRECT
  866:     my $t = Lingua::Text->new(fr => "\x{E9}tude")->encode();
  867:     print $t->fr();    # &eacute;tude
  868: 
  869: =head2 Missing translation returns undef, not an empty string
  870: 
  871: When a translation is not stored for the requested language, C<as_string()>
  872: and the accessor methods return C<undef>, not C<"">.  Use C<defined()> to test
  873: for absence, not a truth check.
  874: 
  875:     my $t = Lingua::Text->new(en => 'hello');
  876: 
  877:     my $de = $t->de();
  878:     print "Missing\n" unless defined($de);   # correct
  879:     print "Missing\n" unless $de;            # WRONG -- also triggers for $de = '0'
  880: 
  881: =head2 Typos in language codes are silent
  882: 
  883: The AUTOLOAD accessor returns C<undef> for any two-letter name that is not a
  884: valid ISO 639-1 code, and also for valid codes that have no stored translation.
  885: A typo like C<$t-E<gt>enn()> produces C<undef> without any warning.
  886: 
  887:     $t->en('hello');
  888:     print $t->enn();    # undef -- no warning, no error
  889: 
  890: To guard against this, always check with C<defined()> and, during development,
  891: consider adding a test that verifies the expected languages are present.
  892: 
  893: =head2 new('text') silently drops the text when no locale is set
  894: 
  895: When you pass a single string to C<new()>, it is stored under the current
  896: system language.  If no locale environment variable (C<LANG>, C<LC_MESSAGES>,
  897: etc.) is set, the language cannot be determined and the text is silently
  898: discarded.
  899: 
  900:     # Safe: locale is set
  901:     $ENV{LANG} = 'en_GB.UTF-8';

  903:     print $t->en();   # hello

  905:     # Unsafe: no locale
  906:     delete $ENV{LANG};
  907:     delete $ENV{LC_MESSAGES};
  908:     my $t = Lingua::Text->new('hello');   # text is lost
  909:     print defined($t->en()) ? $t->en() : 'lost';   # lost
  910: 
  911:     # Safe alternative: always name the language explicitly
  912:     my $t = Lingua::Text->new(en => 'hello');

  919:

  958:

  960: objects stringified per request, same accessor called repeatedly):

  963:

  965:

  970: subsequent calls cost only five string comparisons instead of a full
  971: C<I18N::LangTags::Detect::detect()> scan.  The cache is invalidated
  972: automatically when any of those variables change -- including C<local %ENV>
  973: in tests.

  975: =item B<AUTOLOAD method installation>
  976: 
  977: The first call to any two-letter accessor (e.g. C<$t-E<gt>en()>) installs a
  978: real subroutine in the package symbol table.  All subsequent calls for that
  979: code dispatch directly, bypassing the AUTOLOAD regex and guard overhead
  980: entirely.

  982: =item B<Single-argument fast path in as_string()>
